¿Qué es el proyecto?

El objetivo es implementar y verificar un lazo de control PID aplicado al control de alabeo (roll) de un avión. Para eso construimos un banco de pruebas físico que permite observar la respuesta del sistema en tiempo real.

✈️

El avión

Maqueta de telgopor con forma de avión. Las alas tienen alerones en las puntas, conectados por un varillaje en Y a un único servo. Cuando el servo gira, un alerón sube y el otro baja simétricamente.

🔩

La varilla

El fuselaje está montado sobre una varilla que actúa como eje de alabeo. El avión puede girar libremente alrededor de ese eje (rotar en roll), pero no tiene libertad en otros ejes.

💨

El ventilador

Colocado frente al morro del avión, genera un flujo de aire relativo que hace que los alerones sean aerodinámicamente efectivos. Sin viento, el servo no podría ejercer torque de corrección.

🎯

El control

Un PID corriendo a 100 Hz en el ESP32 calcula la deflexión necesaria de los alerones para mantener el avión nivelado. El setpoint por defecto es 0° (alas horizontales).

Hardware del sistema

Todos los componentes integrados en el fuselaje del avión. Las conexiones reutilizan los cables del encoder KY-040 para conectar el MPU6050:

  • Dirección 0x68 (AD0 pull-down)
  • DLPF a ~44 Hz (corta vibración del ventilador)

Servo de alerones

  • Señal en GPIO 25 (PWM 50 Hz)
  • Pulso: 500–2400 µs
  • Centro en 90° (trim mecánico, ajustable)
  • Rango: 60°–120° (límite mecánico varillaje)
  • Deflexión máx comandada: ±30°
🕹️

Joystick analógico

  • Eje X → GPIO 34 (ADC 12 bit, 0–4095)
  • Pulsador SW → GPIO 32 (pull-up interno)
  • Zona muerta: ±150 cuentas ADC
  • Modo manual: deflexión directa proporcional
  • Pulsador: alterna manual ↔ automático

El lazo de control PID

El PID calcula la deflexión de los alerones en función del error de alabeo. Se ejecuta a 100 Hz. El término derivativo se toma directamente del giróscopo (tasa angular ω) en vez de derivar el ángulo medido, lo que reduce el ruido.

donde e(t) = setpoint − θ(t) y ω(t) es la tasa angular del giróscopo (derivada directa, menos ruido que derivar θ)

Kp = 2.0

Término proporcional. Actúa en función del error actual. Aumentar Kp acelera la respuesta pero puede generar oscilaciones. Con Kp=2 y un error de 20°, la salida es 40° → limitada a 30° por el tope mecánico.

Ki = 0.3

Término integral. Elimina el error en estado estacionario acumulando el histórico del error. Incluye anti-windup: el integrador se acota a ±I_MAX/Ki (I_MAX=20°) para evitar saturación.

Kd = 0.1

Término derivativo. Se usa la tasa angular ω del giróscopo directamente (no se diferencia θ), lo que evita amplificar el ruido del acelerómetro. Amortigua sobreoscilaciones.

Filtro complementario (fusión de sensores)

El ángulo de alabeo θ se obtiene fusionando giróscopo + acelerómetro:

θ(t) = α · (θ(t−1) + ω·dt) + (1−α) · θacc(t)

Con α = 0.98: el giróscopo (rápido, sin deriva a corto plazo) aporta el 98% del ángulo; el acelerómetro (lento, sin deriva) corrige la deriva del giróscopo en el largo plazo. Se aplica un filtro pasa-bajos digital DLPF a ~44 Hz para cortar la vibración del ventilador y el servo antes de leer el MPU6050.

Detalles del firmware

El firmware corre sobre Arduino (ESP32). Destacamos los tres bloques más importantes del código fuente real:

1. Filtro complementario — fusión de sensores

// ALFA_COMP = 0.98 — giróscopo para lo rápido, acelerómetro para la deriva
void actualizarAngulo(float dt) {
  float ax, ay, az, gx;
  if (!mpuLeer(ax, ay, az, gx)) { erroresI2C++; return; }

  anguloAcc = atan2f(ay, az) * RAD_TO_DEG;    // solo acelerómetro (lento, sin deriva)
  float gxCorr = gx - gyroBiasX;              // compensar bias del giróscopo

  anguloAbs = ALFA_COMP * (anguloAbs + gxCorr * dt)
            + (1.0 - ALFA_COMP) * anguloAcc;    // fusión

  anguloAlabeo = anguloAbs - offsetAngulo;     // relativo al cero fijado
  tasaAlabeo   = gxCorr;                       // tasa angular para el término D
}

2. Algoritmo PID con anti-windup

// Corre a 100 Hz (Ts = 10 ms). Anti-windup + D del giróscopo (no diferencia numérica).
float ejecutarPID(float angulo, float tasa, float dt) {
  float error = setPoint - angulo;

  // Integral acotada — anti-windup
  integral += error * dt;
  if (Ki > 0.0001) {
    float lim = I_MAX / Ki;    // I_MAX = 20° → con Ki=0.3: lim = 66.7°·s
    integral = constrain(integral, -lim, lim);
  } else { integral = 0.0; }

  // Derivativo: tasa del giróscopo directamente (sin derivar una señal ruidosa)
  float u = Kp * error + Ki * integral - Kd * tasa;
  return constrain(u, -DEFLEXION_MAX, DEFLEXION_MAX);  // limitar a ±30°
}

3. Interfaz WiFi embebida en el ESP32

El ESP32 levanta un punto de acceso WiFi "PID_Avion" (contraseña: 12345678). Conectarse con cualquier dispositivo y abrir http://192.168.4.1. La interfaz incluye:

  • Gráfico en tiempo real (canvas HTML5): ángulo medido, setpoint, deflexión del servo
  • Sliders para ajustar setpoint (±30°) y ganancias Kp, Ki, Kd desde el celular
  • Botones: Fijar cero, Arrancar PID, Detener, Manual/Automático
  • Endpoint /datos → JSON con angulo, tasa, servo, modo, errores I²C
  • Endpoint /arrancar → calibra el giróscopo, fija cero, activa el PID

⚠ Seguridades implementadas

  • Si el ángulo supera ±60° → servo al centro, integral reseteada (protección mecánica)
  • Si el MPU6050 no responde (error I²C) → servo al centro automáticamente
  • Anti-windup en el integrador: acotado según I_MAX=20° y el valor de Ki
  • Término D tomado del giróscopo (no diferencia de ángulo) → menos sensible al ruido
  • Calibración de offset del giróscopo al arranque: 200 muestras con avión quieto (~1s)
